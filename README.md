# 2D Top-Down Shooter

Siv3D (C++) を用いて制作した、2Dトップダウン形式のチーム対抗型拠点占領シューティングゲームです。  
プレイヤーおよび複数AIによる最大20人規模のチーム戦闘システムを実装しています。
また、本作は**C++の言語仕様・オブジェクト指向設計・パフォーマンスを考慮したプログラミングの学習および技術向上**を主目的の一つとして開発を行っています。

## ゲーム内容・ルール

1. **勝利条件:**
   * マップ内に配置された拠点（A / B / C）を占領することで、敵チームの「チケット」を減らします。
   * 敵チームのチケットを 0 にするか、制限時間内により多くのチケットを残したチームの勝利となります。
2. **AIのチーム戦闘:**
   * プレイヤー（Blueチーム）以外に、味方AI（Blue）および敵AI（Red）が参戦します。
   * 兵士は死亡しても、自チームが占領している拠点から再出撃（リスポーン）します。

## 技術的なこだわり・工夫した点

実務を意識し、「**動くのは当たり前として、保守性・可読性・拡張性の高いコード**」を書くことを重点的に意識して開発しました。

### 1. 状態遷移と兵科（Role）を組み合わせた AI アルゴリズム
単に敵へ向かって進むだけの単調なAIではなく、**状況に応じた思考（State）と役割（Role）に基づく柔軟な行動ロジック**を実装しました。

* **状態遷移（State）:** 
  * `Idle` / `Evade`（弾丸回避） / `Retreat`（HP低下時の撤退） / `Attack`（交戦） / `Capture`（拠点占領）
  * 自分に向かって飛んでくる弾丸のベクトルの内積（`dot`）を計算し、弾が近い場合は緊急回避動作を行うアルゴリズムを導入しています。
* **兵科による差別化（Role）:**
  * **Assault:** 拠点中心へ突撃し、インファイトを展開
  * **Defender:** 拠点範囲内に留まり防衛に特化
  * **Flanker:** 敵の正面を避け、側面（Flank）へ回り込むように移動経路を補正
  * **Support:** 遠距離（SR）から後方支援

### 2. AABBスラブ法を用いた視線判定（Line of Sight）
壁越しに敵を発見して撃ってしまう不自然さを防ぐため、2点間（兵士とターゲット）の線分が障害物の矩形（AABB）と交差しているかを判定する `has_line_of_sight` 関数を独自実装しました。  
不要な描画や判定を削減し、視線が通っている場合のみ交戦状態へ遷移するように最適化しています。

### 3. 可読性と保守性を意識したコード構造
大規模化・長期運用に耐えられる設計を意識しました。
* **ヘッダー分割と構造化:** `Common.hpp`（定数・列挙型）、`GameObjects.hpp`（クラス・構造体定義）、`GameObjects.cpp`（実装）、`Main.cpp`（ゲームループ・描画レイヤー）に適切に役割分離しました。
* **命名規則の統一:** 一目で役割がわかる変数名・関数名を設定し、マジックナンバーの排除（`constexpr` による定数定義）を徹底しました。
* **壁とのめり込み・衝突処理:** 移動処理において X軸と Y軸の衝突判定を分離することで、壁に沿ってスムーズに滑る挙動を実現しました。

## 今後の課題・拡張・実装ロードマップ

現状の実装（ルールベース・FSM による意思決定）から、より高度で自律的な AI システムおよびチーム戦略の構築を目指し、以下のステップで拡張を進めています。

### 1. Utility AI への移行（意思決定ロジックの高度化）
単純な状態遷移（FSM）から、状況ごとに各行動の優先度を数値化して評価する **Utility AI** への移行を予定しています。

* **スコア評価関数の導入:**
  * `score_attack()` : 敵との距離・武器適正・視線判定に基づく攻撃優先度
  * `score_capture()` : 各拠点の占領状況・距離に基づく占領優先度
  * `score_flank()` : 敵の向き・障害物配置に基づく側面攻撃（裏取り）優先度
  * `score_retreat()` : 残りHP・周囲の敵味方数に基づく撤退優先度
  * `score_reload()` / `score_grenade()` / `score_defend()` / `score_heal()`
* **実装方針・設計上の考慮:**
  * 一度に全ロジックを置き換えるのではなく、まずはコード構造として「各行動のスコア計算関数」を独立化・モジュール化して設計。
  * 最終的に `best_action = max(scores)` によって最も評価値の高い行動を動的に選択する設計へとスムーズに移行できるようにベース設計を整えています。

### 2. 部隊（分隊）行動システムの構築
個々の AI が独立して動くだけでなく、グループ単位で連携して戦術を展開する階層型 AI の導入。

* **分隊長（Squad Leader）AI:** 
  * 全体の状況から分隊目標を設定し、各メンバーへ指示（突撃・援護・側面移動など）を発行。
* **役割に応じた班編成:**
  * **突撃班:** 拠点へ最前線で圧力をかける
  * **援護班:** 遠距離・中距離から後方支援および射撃抑制
  * **裏取り班:** 敵の防衛ラインの裏へ回り込み、注意を分散させる

### 3. 戦略 AI（High-Level Strategy AI）の実装
マップ全体（3拠点の状況・チケット残量）をリアルタイムに分析し、チーム全体の戦術方針を決定するメタ AI の実装。

* **大局的な意思決定:**
  * 「A 拠点を一時的に放棄し、B 拠点の防衛を固める」
  * 「チケット劣勢時に C 拠点へ全兵力を集中させて総攻撃を仕掛ける」といった動的な戦略指示の生成。


### 4. リファクタリング
* 死亡処理に関して、deadがtrueやfalseの時に判断するものと、hpが0以下かそうでないかで判断するものが混ざっているため、統一する。
* 各ファイルに同一のリロード処理が何回もあり可読性が低いため、GameObjects.cpp（または GameObjects.hpp）に共通関数を作りMain.cpp も GameObjects.cppではプレイヤーかAIのリロードかで分けるようにする。
